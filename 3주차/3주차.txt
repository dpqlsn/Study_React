이벤트
- JSX에 이벤트 헨들러를 추가할 수 있음
- 이벤트 핸들러 추가를 위해서는 먼저 함수를 정의하고 이를 적절한 JSX 태그에 prop 형태로 전달
- 주로 컴포넌트 내부에서 정의됨
- handle로 시작하고 그 뒤에 이벤트명을 붙인 함수명을 가짐

함수를 전달하기 (올바른 예시)
<button onClick={handleClick}>

함수를 호출하기 (잘못된 예시)
<button onClick={handleClick()}>
- 클릭이 없었음에도 불구하고 즉시 함수를 실행하도록 설계됨

이벤트 핸들러 Prop 명명하기 
- <button>과 <div> 같은 빌트인 컴포넌트는 onClick과 같은 브라우저 이벤트 이름 만을 지원

이벤트 전파
- 이벤트 핸들러는 해당 컴포넌트가 가진 어떤 자식 컴포넌트의 이벤트를 수신
- 부여된 JSX 태그 내에서만 실행되는 onScroll을 제외한 React 내의 모든 이벤트는 전파됨

State
- 컴포넌트는 상호 작용의 결과로 화면의 내용을 변경해야 하는 경우가 많음 컴포넌트는 현재 입력값, 현재 이미지, 장바구니와 같은 것들을
  기억해야함, 이때 이것을 React는 이런 종류의 컴포넌트별 메모리를 state라고 부름

- 렌더링 사이에 데이터를 유지함
- React가 새로운 데이터로 컴포넌트를 렌더링하도록 유발

useState 
- 렌더링 간에 데이터를 유지하기 위한 state 변수
- 변수를 업데이트하고 React가 컴포넌트를 다시 렌더링하도록 유발하는 state setter 함수
- useState를 호출하는 것은, React에 이 컴포넌트가 무언가를 기억하기를 원한다고 말하는 것
- useState의 유일한 인수는 state 변수의 초깃값
- State는 격리되고 비공개로 유지됨

훅
- React에서 useState와 같이 “use”로 시작하는 다른 모든 함수는 훅, 또는 React가 오직 렌더링 중일 때만 사용할 수 있는 특별한 함수

렌더링 그리고 커밋
- 컴포넌트를 화면에 표시하기 이전에 React에서 렌더링해야함

초기 렌더링 
- 앱을 시작할 때 초기 렌더링을 트리거헤야힘

React 컴포넌트 렌더링 
- 렌더링을 트리거한 후 React는 컴포넌트를 호출하여 화면에 표시할 내용을 파악, React에서 컴포넌트를 호출하는 것
- 초기 렌더링에서 React는 루트 컴포넌트를 호출
- 이후 렌더링에서 React는 state 업데이트가 일어나 렌더링을 트리거한 컴포넌트를 호출
- 렌더링은 항상 순수한 계산이기에 동일한 입력에는 동일한 출력을 해야함
- 이전의 state를 변경해서는 안됨

React가 DOM에 변경사항을 커밋 
- 컴포넌트를 렌더링(호출)한 후 React는 DOM을 수정
- 초기 렌더링의 경우 React는 appendChild() DOM API를 사용하여 생성한 모든 DOM 노드를 화면에 표시
- 리렌더링의 경우 React는 필요한 최소한의 작업(렌더링하는 동안 계산된 것!)을 적용하여 DOM이 최신 렌더링 출력과 일치
